# Creator XHS Layout

交付可编辑 HTML、逐页 PNG、总览图和机器可读的检查报告。基于 Ian XHS Carousel 的 20 个母版改编，另有四种参考风格的独立版式；来源及修改范围见 [references/credits.md](references/credits.md)。

## 接收输入

- 已有文案直接使用；只有链接时先取得内容，读不到就说明缺口，不猜写。
- 用户原话、引文、数字、事实归属与判断强度需要保留。改成图上短句时不能删掉影响结论成立的条件。
- 负责图上的标题和说明；帖子标题、正文、标签仅在用户同时要求时另行处理。可以接收 MyContent 的成稿，但不依赖它才能运行。
- 取得主题、输入材料与输出目录；能从当前项目确认时不重复询问。遵循当前项目目录规则，原素材只读，写入独立的新输出目录。
- 如果素材包含个人经历、真实产品状态、效果数据等证据缺口，集中列出缺口；不要拿生成图替代真实凭据。

## 选择风格与分镜

先读 [references/style-guide.md](references/style-guide.md)，再根据内容选择；用户指定的优先。五种风格是五个入口，不是五种颜色覆盖同一母版。

| 标识 | 用途 | 模板 |
| --- | --- | --- |
| `product-ui` | 软件演示、功能对比、工具清单、步骤 | Ian 的 T01–T20 |
| `research` | 研究、方法论、观点论证、实践复盘 | R01 封面 / R02 论述页 |
| `archive` | 主题收藏、材料研究、创作过程 | A01 静物封面 / A02 档案页 |
| `dramatic` | 有明确冲突或转折的单一主题 | D01 戏剧封面 / D02 解析页 |
| `blueprint` | 概念解释、教程、知识链路 | B01 封面 / B02 知识卡 |

没有指定时选择最适合的一个，并给出一句依据，不把本次选择写成永久偏好。允许戏剧封面接克制正文；必须说明组合，页码、栏目、字体层级保持一致，不把所有装饰叠在一页。

给出简短分镜：页码、该页唯一要点、图上标题、风格/母版、证据或配图来源。按内容需要决定页数，不机械套用“必须五页”，也不把每个原文段落都做成一页。

- 用户明确要求先看方案，或关键事实/风格尚有歧义时，等待对应确认。
- 主题与材料已清楚、用户要求直接制作时，展示分镜后继续执行，不额外插入审批轮次。
- 不默认添加推广署名、二维码、关注提示或互动诱导。作者/栏目字段只使用用户实际提供的值。

## 准备素材

区分用户提供的照片/截图、依据数据绘制的图解、生成式插画，并在交付中说明。

- 产品界面：读 [references/upstream/layouts.md](references/upstream/layouts.md)，从 [assets/upstream/templates.html](assets/upstream/templates.html) 选 T01–T20。规则和图解分别见 [references/upstream/design-system.md](references/upstream/design-system.md)、[references/upstream/figures.md](references/upstream/figures.md)。
- 其他四种：从 [assets/creator-templates.html](assets/creator-templates.html) 选择对应片段，遵循风格说明的留白、构图和素材要求。不要仅给产品卡片换色。
- Archive 封面需要围绕主题组织的静物照片/生成图，戏剧封面需要原创场景图；没有时请用户提供、使用当前 Agent 可用的图像工具，或明确只交付分镜和出图提示词。排版脚本不生成照片或动画图像。
- 图像生成按当前工具的权限和计费约束执行；没有可用工具时不要声称已生成。不假定其他 Agent 拥有某个专用 MCP 或 API 密钥。
- 生成主视觉时预留标题区，标题、正文、数字和图表标签随后用代码叠加。真实截图与真实照片不改写成虚构证据。
- Eagle 是可选的本地参考来源，不是运行依赖；用户未提供 Eagle 时，Skill 仍可用自带版式工作。第三方 Eagle 收藏图默认不进入分发包。

## 排版与渲染

复制 Skill 的 `assets/` 到本期制作目录，创建 `index.html`，链接 `assets/upstream/xhs.css`、`assets/creator.css`；图标/图解需要时再加载上游 JS。每页固定 1080×1440：

```html
<section class="slide cx-page" data-style="research" data-layout="R02 论述页">
  <!-- 填入对应模板的真实内容 -->
</section>
```

产品界面页继续使用上游 `.slide` 及 T 母版；可在 `body` 设置 `data-style="product-ui"`。`--theme dark` 只接受纯产品界面图组，其他风格有各自配色，不能自动反色。

字体使用本机已安装的中文字体，不携带商业字体文件。默认不访问在线字体服务。需要固定字体时，使用用户已授权的本地字体，并在本期 CSS 声明 `@font-face`；不把本机绝对路径写进分发包。

运行环境与安装方式见 [references/runtime.md](references/runtime.md)。依赖已经存在时复用，无需重复安装。

```sh
node <skill目录>/scripts/render.cjs <制作目录>/index.html <新的输出目录>
```

渲染脚本从 Ian 的渲染流程改编为 Node，导出 `01.png` 等逐页图、`overview.png`、`qa.json`。检查失败时退出码非零，不能作为最终交付。输出目录必须不存在；重做时使用新版本目录，避免覆盖用户文件。

## 检查与交付

1. 检查 `qa.json`：尺寸、文本越界、父容器裁字、图片加载、页面脚本报错、未替换 `.ph` 和字号问题都必须解决；产品界面的一处橙限制只作用于产品界面页。
2. 打开总览，再打开每页原尺寸 PNG，核对中文、断行、事实与来源、对比关系、阅读顺序和缩略图可读性。机器检查通过不等于视觉检查通过。
3. 无法从截图确认细节时，明确剩余问题；不要宣称发布效果已验证。
4. 交付总览、逐页图、HTML 源文件和实际输出路径，说明风格/模板选择、素材来源和仍需用户补充的内容。

完成图组与当前相关验证后结束，不自动发布小红书，不自动提交或推送仓库。Skill 自身的改动和发布按用户当次授权执行。
